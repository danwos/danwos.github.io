title: "Moving legacy data to docs-as-code"
summary: "A proof of concept at a Tier-1 supplier: requirements, specifications, code and tests of an ECU project in a docs-as-code toolchain – the model was later rolled out across the whole company."
industry: "Automotive, Tier-1 supplier, ECU development"
team: "Project with about 500 people; proof of concept with 3 people and about 40 users"
period: "2025"
role: "Consulting and implementation"
order: 20
problem: |
  An ECU project with about 500 people had collected data in classic tools for years: software requirements, specifications, code and tests – maintained separately and hard to connect.

  Docs-as-code sounded promising. But nobody knew whether it would work with real legacy data and the demands of an automotive project. Before switching, the company needed proof.
approach: |
  In a proof of concept, a team of 3 moved the legacy data into a docs-as-code toolchain from useblocks: software requirements, specifications, code and tests, linked and traceable in one documentation.

  About 40 users worked with it in their daily project work. For the hardware requirements, we created a concept for fitting them into the same structure.
result: |
  The proof worked: legacy data and new content live in one shared, linked documentation, and the teams work in the tools they already know.

  Based on this, the company later rolled out docs-as-code company-wide.
