## Why monsterbrain

<Scene monster="monsterbrain-crying" alt="monsterbrain crying big tears" />

Working with AI agents often feels like working with a very clever colleague
who has no memory. Every session starts from zero. What you explained
yesterday is stuck in an old chat, in a `CLAUDE.md` that keeps growing, or in
the comments on a pull request. And at some point nobody knows any more what
of it was confirmed and what was just a draft.

I run danwos with AI agents that take care of product, tech, marketing and
legal. They need one place where they all find the same knowledge – and where
it is clear what holds. That is where monsterbrain comes from: a single folder
that people and agents read and maintain alike.

## One folder, clear layers

monsterbrain is not a program with a database but a folder structure of plain
Markdown, YAML and JSON, versioned with Git. Every layer has a clear job and
clear rules about who may read and write there.

| Folder | What lives there | Who writes |
|---|---|---|
| `20_facts` | the verified truth, binding wording included | only through an approval |
| `10_concepts` | work in progress, one folder per concept | freely, in your own concept |
| `30_outputs` | finished results: PDFs, slides, pages | store only |
| `40_sources` | evidence and third-party material, unchanged | store only |
| `50_assets` | logos, fonts, templates | after asking |
| `90_archive` | closed concepts, legacy material | only by moving |
| `00_system` | agents, skills, templates, scripts | after asking |

Every file starts with a short summary. An agent reads that first and then
decides whether to read on. That saves tokens and keeps the context lean.

## How knowledge grows

Agents never write straight into the facts. They work in a concept and collect
evidence, drafts and open questions there. Only when you approve the concept
does the skill `close-concept` hand out the results: findings move into the
facts, finished files into the outputs, the concept into the archive.

<KnowledgeFlow lang="en" />

In the app you see every concept with everything that came out of it – even
once it has long moved into the facts or the outputs.

<Screen src={concepts} alt="The concepts view of monsterbrain: open and closed concepts on the left, one expanded with its results, the concept itself in the middle." />

Every fact lives in exactly one place. When two statements contradict each
other, the agent reports it instead of guessing.

## Agents and skills

<Scene monster="monsterbrain-flying" alt="monsterbrain flying with arms stretched out" left />

Every role is a single Markdown file: what it does, what it reads, where it may
write. Tools like Claude Code load these files directly, there is no second
configuration. Recurring workflows are skills – starting a new project,
closing a concept.

On top of that there is a fixed reading order: the rules first, then the
index of the matching folder, then only the summaries, and single files last.
The agent quickly finds what it needs without reading the whole folder.

## Work and private life, cleanly separated

<Scene monster="monsterbrain-relaxed" alt="monsterbrain lying relaxed on its side, head propped on one hand" />

One brain, several worlds: company, club, house and family can all live in the
same monsterbrain, each in its own area. The areas share nothing, each has its
own rules, its own roles and, if needed, its own language. An agent always
works in exactly one area and does not see the others.

In mine, the company and the founding of a club sit side by side without
anything getting mixed up.

## See how it all connects

Folders and files are ideal for agents, but tiring for people in the long run.
So monsterbrain also comes as a desktop app: the file tree on the left, the
file in the middle the way it is meant to be read – Markdown rendered, HTML
live, translations as a table. Top right, a graph shows what the file links to
and what links to it, below it its metadata and what to check: a broken link,
a missing summary, an outdated date.

<Screen src={files} alt="The monsterbrain app: the file tree with the changed files on the left, a rendered company profile in the middle, the graph with all links, a check note and the metadata on the right." />

One click on a link or a node in the graph and you are in the next file. The
colours show the layer, so you see at a glance whether a fact is properly
backed and which concept is working on it right now.

## See what the agents changed

After one round with Claude, a dozen files have quickly changed: a fact, a web
page, a translation, a picture. The change view lists them all, and every
change shows the way it is meant to be read – the web page before and after
side by side, the changed paragraphs marked in Markdown, only the changed
entries of a translation.

<Screen src={changes} alt="The change view: the five changed files on the left, a web page before and after side by side in the middle – new price, new text." />

Claude steers the app along the way: it opens the file it is talking about,
highlights the passage and shows what it changed at the end.

## What's in the repository

The repository contains the complete structure to get started: the folders,
the rules for agents, templates, skills, roles and a few scripts. It also
ships an example brain with made-up content – a small design studio and a
private area. It shows how everything fits together, the tutorials build on
it, and it doubles as test data.

<Screen src={welcome} alt="The welcome page of the example brain in the viewer, with monsterbrain in the picture." />

```text
example-brain/
├── AGENTS.md          rules for all agents
├── README.md          start here
├── 00_system/         skills, templates, scripts
├── studio/            the company
│   ├── AGENTS.md
│   ├── 00_system/agents/
│   ├── 10_concepts/
│   ├── 20_facts/
│   ├── 30_outputs/
│   ├── 40_sources/
│   ├── 50_assets/
│   └── 90_archive/
└── home/              private, cleanly separated
```

The texts are under the MIT licence. The monsterbrain pictures live in a
separate folder with their own licence and stay protected.
